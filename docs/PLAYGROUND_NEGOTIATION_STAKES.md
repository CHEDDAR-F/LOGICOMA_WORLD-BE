# Odd Shop rule 1.2 — consequences of negotiation

Candidate only. `PLAYGROUND_STAKES_ENABLED=false` is the default; enabling it selects 1.2 for new annual FULL rooms with the existing v6 gate. Saved 0.4–1.1 rooms retain their rules. No new migration is required. Deploy a compatible Host (internal schema 8 / wire contract 5) and the schema-6 anonymous renderer before activating new rooms.

`V8NegotiationStakes` resolves each incident from its public card economics. The second/third option no longer silently adds legacy promotion/pivot fees or changes the signed price. Previous rent and active customer/supply effects still apply when a fresh crisis occurs.

If a monthly negotiation has no effective plan, the original signed operating strategy remains the fallback. This does **not** erase the incident: the task explicitly exposes `unresolvedEffect`. A shortage or closure limits trade; a rent increase charges the published surcharge and persists it. Unsigned order, event and exclusive-supplier opportunities expire, granting neither income nor new commitments. Deadline, budget and model failures remain distinct resolution reasons, not fabricated Agent disagreement. Community trust is customer reputation, never interpersonal trust.

After settlement the service records `decisionImpact`: actual monthly accounts, both independently proposed initial plans (if submitted), and the signed fallback under the same immutable starting inventory, cash, market seed and existing contract. Alternative simulation does not mutate the room or call a model. It explains the current month only, not an alternate full-year story or an Agent's causal effect on the final outcome. Equivalent plans can have equal accounts. A failed opening uses zero current-month sales and its liquidation equity change, not the preceding report's sales/profit.

Public schema 6 copies only this finite account structure, not rationale, owner guidance, identities, task tokens or arbitrary metadata. Existing schemas 3–5 remain readable. The snapshot validator rejects extra fields inside counterfactual account records.

Tests include version persistence, sealed opinions, a declined first monthly negotiation, all 12 operating months, independent terminal reviews, schema-6 readback and a nested private-canary rejection. All use a fresh localhost MySQL database and deterministic Agent decisions; they are not model-quality or production acceptance. Pure tests cover exact costs, inactive opportunity consent, same-market comparison, equivalent choices and failure-before-opening.

This slice does not add asymmetric owner goals, cross-month orders, interpersonal scoring, audience voting or invitations. Those need their own finite rules and consent paths. Increasing model hostility is not a rule mechanic.
